# 手机端与电脑端独立工程

`desktop/` 和 `mobile/` 是两套完整工程，可分别复制到空目录、初始化自己的仓库并独立部署。两端互不隶属、互不干涉，各自修改、测试与发布，不自动同步。两端拥有自己的源代码、预构建脚本、运行图片、原画、PSD、Live2D 模型及可编辑工程、测试、工具、许可证与依赖锁文件。源文件和素材均为真实副本。

根目录保留原项目代码与素材作为迁移备份。现有未提交修改也已进入两套新工程。今后的游戏开发在对应版本目录进行；根目录的两个 HTML 只负责分流。

## 游玩与开发

- 电脑版：打开 `desktop/frontier.html`，使用键鼠操作；触控电脑也保持电脑布局。
- 手机版：打开 `mobile/frontier.html`，使用摇杆和触控按钮；竖屏自动旋转游戏区域。
- 原入口：打开根目录的 `index.html` 或 `frontier.html`，自动识别主指针能力并记住手动选择。
- 选择页：在根目录入口后加 `?choose=1`；强制版本使用 `?client=desktop` 或 `?client=mobile`，恢复自动识别使用 `?client=auto`。

直接打开 HTML 无需安装依赖。修改源码时，进入对应项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm run preview
```

默认预览地址为 `http://127.0.0.1:8080/frontier.html`。两端同时预览可给其中一个指定端口：`pnpm run preview -- 8081`。

## 部署与版本切换

每个新项目都能直接发布到静态网站，无需父目录或另一端。游戏标题页与设置页提供版本切换，并在离开前保存当前进度。

分别修改根目录的 `deployment-config.js` 及两个新项目各自的 `js/deployment-config.js`，填写正式版本地址。默认地址适用于当前双目录预览。单独部署一个版本时，可以把另一版本地址设为 `null`，隐藏切换入口。跨域发布后，版本切换只负责跳转。

本轮没有创建远程仓库或发布线上网站。准备新仓库时，在选中的完整工程副本内初始化 Git；不要复制原仓库的 `.git`、开发依赖或测试产物。

## 独立存档

- 电脑版：`ashen-frontier-save-v3-desktop`。
- 手机版：`ashen-frontier-save-v3-mobile`。
- 旧统一存档：`ashen-frontier-save-v3`，继续保留。

每端第一次启动且没有本端存档时，会读取同一浏览器、同一来源可访问的旧档，沿用现有 v2～v6 迁移逻辑，规范化后写入自己的存档键。已有本端进度优先，后续两端互不覆盖。旧版本备份也使用各端自己的前缀。同端标签页继续同步，另一端的保存不会触发同步。

本地文件的存储权限由浏览器决定。换设备、换域名或旧档不可访问时，使用游戏设置中的 JSON 导出与导入；导入导出格式继续使用 v6。

## 验收

在各自项目目录执行：

```sh
pnpm run test:setup
pnpm test
pnpm run test:regression
pnpm run test:standalone
```

默认使用 Playwright 安装的 Chromium，也可用 `CHROME_PATH` 指定已有浏览器。独立性验收会复制整套工程到系统临时目录，排除依赖与产物，从锁文件离线安装依赖、重新构建并运行游戏验收，结束后清理临时目录。离线安装需先在原目录成功安装一次依赖。

根目录的 `node tests/client-routing.cjs` 验证分流、记忆选择、跨版本跳转、旧档继承与双端存档隔离，使用电脑版已经安装的 Playwright。验收报告与截图保存在各自的 `artifacts/`，不会进入版本控制。

制作原稿已完整复制，并取消了新工程中对 `assets/art-v2/sources/` 的忽略。历史 Git 对比或恢复工具仍需要相应原版本历史；常规构建、游玩和验收不需要原仓库。
